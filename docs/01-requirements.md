# 需求与成功标准

## 用户、目标、范围

面向员工和知识维护人员，回答小型合成制度与产品库中的问题。优先保证原文可核查、冲突可见、无资料时停止。交付 CLI，采用 Python 标准库和可替换模型接口。UI、部署、多 Agent、权限系统、真实企业资料不在本次实现范围。

输入为问题、可选 user/assistant 历史和资料文件。历史用于解析追问主题，知识依据来自本轮工具读取。资料必须包含唯一文档 ID、版本日期、标题、主题、适用范围、规范值和原文。

输出为原文式回答、引用 ID、版本日期、原文片段、原文哈希、资料缺口、冲突与任务状态。当前小文档直接引用全文，以免片段截断否定或条件。

## 成功标准

| 场景 | 可检查的行为 |
|---|---|
| 明确答案 | 检索并读取 P01，引用原文；不添加效率或准确率数据 |
| 文档冲突 | 读取 D01 和 D02，同时列出 30 天、15 天依据，要求确认适用制度 |
| 资料外问题 | 尝试补充检索后返回 out_of_scope 和资料缺口 |
| 相似改写 | “垫付后费用单最晚何时交”召回报销制度，保持冲突状态 |
| 上下文追问 | 根据此前用户提到的报销解析“那期限呢”，重新检索并引用 |
| 工具失败 | 暂时失败允许模型选择重试，持续失败达到预算时 incomplete |
| 证据不足 | 模型未经读取就声称有答案时，校验器拒绝结束 |
| 资料变更 | 替换 P01 原文后，输出引用和哈希随之改变 |

默认最多 12 次模型决策，所有动作纳入预算，达到上限显式返回未完成。工具只读；每次运行的对话、引用、Trace 状态独立。

## 需求证据层级

离线 Mock 验证可执行性、状态边界、失败处理和引用约束。真实模型使用本地 Qwen3-1.7B，记录检索、原文读取、冲突判断与工具故障后的不同动作。两类证据分别保存在 examples 的离线目录与 live 目录；空问题由输入校验直接请求补充，Trace 明确 model_called=false。
